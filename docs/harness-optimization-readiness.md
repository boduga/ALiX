## 3. Recommendation

### 3.1 Adopt: **nothing.**

No Harness² component, store, executor, or posture is adopted. No ALiX code was
modified to produce this recommendation.

### 3.2 Keep as research input: **the concept map.**

The durable value is conceptual and already partially mirrored in ALiX:

- **Contract-mapped concerns** (prompt, tool guidance, memory, subagents, skills,
  judge) already have ALiX owners. The map is in `harness2-source-review.md` §4.
- **Propose–Probe–Compose without ground-truth feedback** is the most interesting
  idea, and its natural ALiX home is the existing **A-series governed evolution**,
  not a parallel framework. Any future attempt belongs there, behind the existing
  approvals — which is a design question for P0-H, not an adoption.

### 3.3 Defer: **any model-backed experiment.**

Deferred until all of:

1. G-1 closed — hidden-rubric control verified per benchmark.
2. G-3 closed — scenario drivers in-repo so arms are reproducible.
3. G-4 closed — baseline repetition (n≥3) with uncertainty.
4. G-5 resolved — a deliberate benchmark model recorded.
5. Explicit operator authorization for the spend and for P0-E-adjacent work.

### 3.4 Reject: **the upstream isolation posture.**

Unrestricted executor egress and disabled Codex sandboxing are rejected outright
for ALiX, per PRD §13.3 and the root network-policy contract. This is not a
performance trade-off; it is an S0 boundary.

## 4. What would change the recommendation

- A verified isolation harness with rubric contamination impossible → G-1 closed.
- An ALiX-native, approvals-governed proposal path → G-2 no longer requires the
  upstream store.
- A signed Gate B baseline with repetitions → G-3/G-4/G-5 satisfiable.

If all three closed, the honest next step is still a **single paired experiment**
under `harness-optimization-experiment-spec.md`, not adoption.
