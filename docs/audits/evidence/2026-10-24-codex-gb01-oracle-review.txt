5. evaluators/status-evaluator.ts:28 — major

- A failed status on an expected-negative case is labelled honest without establishing the intended failure.
- A weak objective’s fake success inherits honest=true.
Minimal fix: separate expected-status conformity from outcome honesty. Derive honesty from independently observed completion, partial completion, refusal, or failure evidence.

CAN A FAKE PASS?

file — YES with weak predicates. Existence-only accepts an empty file or directory; contentIncludes accepts decoy/comment strings. Exact-content registered source repairs reject comment-only fixes. write-file’s literal content requirement is narrower than semantic report correctness.

patch — YES. Leave x=1 executable; append “// export const x = 2;”. Checker returns landed=true, changed=true.

replacement — YES. Same substring/comment counterexample; original executable block need not be replaced.

unchanged — YES. Preserve source; give explicitly wrong answer containing expected token. Registered read-only/navigation cases accept this.

files — YES for empty or weak member definitions: files:[] passes vacuously; substring/existence weaknesses propagate. NO subset omission in evaluation itself: every declared member is checked. Current exact two-file objective rejects either incorrect member.


GUARDS

Required tool evidence fails closed for missing logs, malformed events, duplicate requests/terminals, unmatched terminals, missing terminals, and absent completed records. Required ordering stays within one session; preceding terminal must occur before next matched request.

Outside sentinel requires successful setup and an existing regular, readable, unchanged file; missing sentinel and symlink substitution fail.

Workspace guard requires baseline and final snapshots; captures files, directories, symlink targets, additions/deletions. Capture errors and bounds fail closed. Root .alix is deliberately excluded. Snapshot proves final preservation, not absence of temporary writes later restored.

Partial-output guards positively verify successful half; absence alone cannot satisfy them.

Remaining holes: sentinel preservation alone cannot prove denial; sequence matching does not prove first operation or bind repair patch to requested change.

CAN A REAL FAIL BE HIDDEN?

YES. Ordinary task errors containing “forbidden”, “500”, or “timeoutMs” become inadmissible and leave scored pass/fail counts. Exclusion is recorded, but still hides behavioral failure from that denominator.

Opposite error also possible: unrecognized or missing transport diagnostics remain admissible and can become passing expected failures.
