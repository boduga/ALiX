## Remediation

### Finding 1 (HIGH) — live-owner age-only theft

`src/governance/approvals/approval-store-lock.ts`: liveness is now authoritative. A valid PID that is provably ALIVE (signal-0 succeeds, or `EPERM` for a process we cannot signal) is **never** reclaimed on age alone; a valid provably-DEAD PID is reclaimed immediately (no age gate). Age is applied **only** when the owner cannot be proven (invalid/missing PID, missing/malformed metadata).

### Finding 2 (MEDIUM) — invalid-PID immediate theft

Invalid/missing `pid` no longer returns stale immediately. It falls through to the age backstop (metadata timestamp), so a recent record stays respected and only an aged-out unprovable record is reclaimed.

### Finding 3 (MEDIUM) — missing-meta recovery stall

A `meta.json`-less directory is aged on its mtime: a young directory is a live writer's `mkdir`→write window (never stolen), an old one is a SIGKILL orphan (reclaimed after the ceiling). Malformed metadata is treated the same way — fail closed while recent, reclaimed after the directory ages out.

### Ownership-safe atomic reclaim (all three)

`reclaimStaleLock` replaces the check-then-`rmSync` race with a POSIX `rename` of the lock directory to a unique tombstone: exactly one contender wins, the winner re-verifies the frozen copy before destroying it (or restores it if the re-check proves a live owner), and the loser's rename throws and simply retries. This closes the double-steal where two contenders both observe a dead owner and both enter their critical sections.

### Finding 4 (LOW) — throw-vs-`outcomeUnknown` contract

Documented in `src/capabilities/tools/types.ts` (`outcomeUnknown` JSDoc) and `src/capabilities/tools/AGENTS.md`: the flag is a **return**, not a throw — an adapter that applies an external effect and then throws retires its single-use approval `failed`, so indeterminable post-effect outcomes must resolve to `{ kind: "error", outcomeUnknown: true }`. Behavior was already consistent across both dispatch routes; this is contract documentation, not a behavior change.

### Finding 5 (LOW) — F-R03 vacuity

`tests/security/d9-full-daemon.test.ts`: dropped the unreachable `denied` member from the asserted terminal-state set and documented that `revoke` (effective on every state except `consumed`/`expired`) supersedes `deny` under contention. The deny actor is still exercised; it just cannot win against a concurrent revoke.

## Remaining uncertainty (report)

1. **PID reuse is not disambiguated.** A valid PID that reads alive via `kill(pid, 0)` is treated as a live owner and never reclaimed, including when the PID has been recycled by an unrelated long-lived process. The original age bound was intended to cover this; the review's Finding 1 makes age-alone-theft a blocking defect, and a correct PID-reuse disambiguator (`/proc/<pid>/stat` start time, or an OS-released `flock`) is a larger change left out of scope. Practical impact: a recycled-PID lock stalls until manual cleanup. This is fail-safe (never theft), not fail-open.
2. **A writer SIGSTOP'd/starved for >60 s in the `mkdir`→write window** could have its metadata-less directory reclaimed (aged out), and its late `writeFileSync` would then overwrite a successor's `meta.json`. The normal live writer's window is two adjacent synchronous syscalls (microseconds); stealing it requires a process frozen at that exact boundary for a full stale ceiling. This is the residual the review itself flagged as the trade-off of aging out a metadata-less lock, and is strictly narrower than the `e9570112` regression it replaces. Not eliminated without an OS-released lock primitive.
3. **Tombstone leak on crash-during-reclaim.** If a process dies between the `rename` and the `rmSync` of a tombstone, an inert `approvals.lock.stale-<uuid>` directory remains. It never matches the lock path and never blocks acquire, so it is a disk-hygiene issue only.
4. **Finding 4 is documentation, not a code guarantee.** An adapter that throws after applying an external effect still retires its approval `failed`; only the return-path contract is now documented. Production setters of `outcomeUnknown` remain `coordination-tools.ts` only.
