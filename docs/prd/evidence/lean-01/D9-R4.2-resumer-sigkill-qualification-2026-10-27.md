## Executed boundary and oracle

`tests/security/d9-resumer-sigkill.test.ts` seeds an actual executor approval
pause, blocked daemon-hosted worker and host-attributed continuation through
the production APIs. It approves the exact invocation, closes the parent's
ledger connections, and spawns `tests/fixtures/d9-resumer-crash-child.ts`
(compiled to JavaScript). The child constructs the real ApprovalWatcher,
DaemonToolContinuationResumer, executor, continuation manager, ownership
registry, event log and SQLite-backed stores. No provider or model is called.
The child has a minimal environment and disposable HOME/workspace.

Test-only wrappers await the original production methods before sending an
IPC checkpoint and parking indefinitely. The parent waits for that checkpoint,
sends actual SIGKILL and asserts the OS exit signal. It reads committed state
after death, then starts two successive fresh child hosts, each running two
watcher scans and two direct resumer calls. Recovery children must exit zero
and have a different PID from the killed child. No locks or leases are deleted
or aged by the test. A timed-out checkpoint fails the test.

The real file router writes `owned.txt`. An independent append-only
`router-entries.jsonl` observation records every router entry, so a repeated
identical-content write cannot hide replay behind file.create idempotency.
Content and mtime are checked as additional evidence. The append is test
instrumentation, not an external transactional effect or an authorization seam.

| SIGKILL checkpoint | State observed after death | Recovery observed |
|---|---|---|
| Before watcher/resumer invocation | Approved; continuation present; no effect | Executes once, consumes exact approval successfully, removes continuation, worker pending at attempt 1 |
| After actual continuation removal returns, before consumption | Approved; continuation tombstoned; no effect | Remains blocked; no execution, no inferred receipt or reconstructed continuation |
| After actual consumption returns, before router entry | Consumed/pending; no effect; original worker/attempt recorded | Remains blocked and consumed/pending; no router entry |
| After real file router returns, before outcome recording | File present; one router entry; consumed/pending | Remains blocked; no second entry or file rewrite; no inferred success |
| After successful outcome recording returns, before worker update | Committed consumed/succeeded; file present; worker still blocked | Repairs worker to pending at attempt 1; approval unchanged; no router entry or file rewrite |

The first checkpoint is a positive restart control before entering the resumer,
not a kill inside its pre-consumption validation. The tombstone checkpoint is
inside the actual resumer path. Pending outcomes intentionally stay pending:
the watcher skips uncertain consumed claims, and the resumer does not classify
them as unverified. This evidence proves denial/no replay for these states,
not automatic uncertainty classification or eventual progress. A tombstoned,
unconsumed approval is likewise stranded safely rather than automatically retried.

## Missing windows and limits

- **Full daemon executable and socket lifecycle:** not qualified. An attempted
  daemon child exited before a checkpoint; a direct private Unix-socket bind
  returned `EPERM` under this sandbox. The unexercised daemon harness was removed.
  These tests execute the actual resumer in a dedicated OS host, not
  daemon-server startup, daemon-manager, RPC or the worker scheduler. Repeat
  the matrix through the full daemon on a host allowing private sockets.
- **Inside ledger/projection writes:** checkpoints follow method completion;
  they do not interrupt SQLite commits, fsync, projection writes or the interval
  immediately after the tombstone append but before remove returns. SIGKILL
  is process death, not machine power loss or storage failure.
- **Additional pre-consumption and post-receipt intervals:** no kill during
  validation/lease acquisition, after consumption but inside tool.started,
  during the file write, or inside the locked worker update. The two receipt
  boundaries exercised do not enumerate every instruction-level window.
- **Competing OS processes and changing authority:** recovery hosts here are
  successive, not simultaneous. Concurrent consumers/resumers, cross-worker
  forged receipts, and cancellation, attempt/scope changes or lease loss racing
  dispatch still need process-level adversarial qualification. Existing focused
  parity/cancellation tests remain supporting evidence, not this missing proof.
- **Arbitrary external effects:** no shell/API/plugin/provider effect,
  idempotency key or distributed transaction is exercised. No global
  exactly-once guarantee follows from the sentinel or approval claim.
