## Executed boundaries

`tests/security/d9-process-races.test.ts` seeds real executor approval pauses,
host-bound continuations and blocked daemon worker records. It spawns compiled
`tests/fixtures/d9-process-race-child.ts` with disposable workspace/HOME and
minimal environment. Each consumer/resumer is a distinct OS process with its
own stores, connections and module state. No provider/model is called.

The four consumers load approved state before reporting readiness; the parent
releases their IPC barriers together. OS scheduling chooses the winner; the
asserted invariant does not depend on which PID wins. Resumer contention is
forced by parking one host at committed `tool.requested`, before the claim,
while a second independent host completes its attempt. The first host holds
its production continuation lock and lease throughout this overlap. The parent
is also the independent authority-changing OS process: it uses production
CoordinationStore updates and OwnershipRegistry revocation/acquisition, not
hand-edited projections, stale lock deletion, or artificial expiry.

Instrumentation wraps EventLog.append **after** the real append to pause at
`tool.requested` or `tool.started`, and wraps executor resume to observe the
actual AbortSignal. It never substitutes an allow/deny result, consumes on
behalf of a gate, or injects a cancellation controller. The FileToolRouter
wrapper records entry, invokes the original router, and optionally appends the
explicit external-effect surrogate after successful file creation. These are
test-only scheduling/observation seams; security boundary code and durable
stores are real. Checkpoint/exit timeout is test failure, never a skipped case.

| Case | Observed oracle |
|---|---|
| Four independent approval consumers | Exactly one successful production consume; consumed/pending attribution retained; zero router entries |
| Concurrent resumers with winner paused before claim | Contender exits without dispatch; winner's exact active lease record unchanged; winner subsequently succeeds once, worker pending at attempt 1, no active lease left |
| Durable cancellation, attempt increment, scope replacement at `tool.requested` (3 cases) | Real 100 ms host monitor abort observed; zero router entries/effects; approval stays approved; continuation tombstoned; worker remains cancelled or blocked with current attempt |
| Same three changes at committed `tool.started` after claim (3 cases) | Monitor abort observed before release to router; consumed/cancelled receipt; original worker attempt cannot be requeued or overwritten; zero effects |
| Lease revoked and conflicting owner acquired before ownership gate | Gate denies, no consumption/effect; competing owner's lease survives cleanup |
| Lease revoked and conflicting owner acquired after claim | Real 10 s renewal observes loss and aborts; consumed/cancelled, zero effects, replacement owner's lease survives |
| SIGKILL after real file effect + nontransactional append, before receipt | One entry/effect, consumed/pending, blocked worker; two simultaneously released fresh recovery processes leave the entire authority/worker/continuation/router snapshot and append unchanged |

The append in the final case is an **external-effect surrogate**, deliberately
outside the approval ledger transaction. It is not a real remote API, plugin,
provider or shell effect, nor a mock authorization boundary. SIGKILL is observed
as the actual OS exit signal before recovery starts. Refusing to replay an
ambiguous consumed claim is the property established. There is no distributed
transaction, universal exactly-once guarantee or inferred success from silence.

## Remaining windows and operator-host reproduction

A direct `node:net` bind to a disposable private Unix socket exited 1 with
`EPERM` in this sandbox. **Full daemon socket startup/RPC/scheduler qualification
was not run and did not pass here.** The child hosts above instantiate the real
resumer; they are not the full daemon executable.

On a Linux operator host permitting private Unix sockets, first compile and run:

```sh
node --test --test-isolation=none --test-reporter=tap dist/tests/security/d9-process-races.test.js dist/tests/events/d9-daemon-restart-e2e.test.js
```

The existing daemon test supplies actual listener/ping, graceful restart and
completion-reconciliation coverage. It does **not** turn these isolated resumer
races into full-daemon race qualification. Reproduce that missing matrix with
this explicit harness design (not implemented or executed here):

1. Retain the same disposable fixture and exact approval/worker/attempt pins.
   Start compiled daemon-server with `--cwd <workspace> --socket <private.sock>`
   and a disposable HOME/config, no real provider credentials. Require both the
   listening log and a successful JSON-line `ping`/`pong` exchange. Capture PIDs,
   Node version, commit, config hash, stdout/stderr and durable snapshots.
2. Load the same IPC barrier wrappers through a test-only Node preload in the
   daemon process, filtering on the target approval/session. Use its actual
   startup ApprovalWatcher/resumer composition, never construct a replacement
   resumer in the preload. Disable model-backed continuation of the seeded
   worker after requeue; retain production scheduler and policy decisions.
3. At `tool.requested`, launch an independently ready resumer contender against
   the same workspace; require it to finish while the daemon is parked. Compare
   exact lease IDs/records before and after, then release the daemon and assert
   one claim/router entry and no authority reissue.
4. Repeat each requested/started authority-change row above using a separate
   mutation host and actual stores; for cancellation additionally exercise the
   public daemon cancel path for a real daemon task enclosing the run. Require
   durable cancellation and actual signal observation, not merely a successful
   RPC response. Revoke/reacquire leases using production APIs. Assert no stale
   attempt promotion and no release of the replacement owner's lease.
5. SIGKILL the daemon at the effect-before-receipt barrier, assert its exit
   signal, and restart the executable with the same HOME/workspace. Use an
   unrelated later watcher-scan sentinel as a completion barrier so negative
   assertions cannot pass before recovery scans run. Require unchanged pending
   authority, no second effect, and retained blocked state. Never delete/age
   locks to make recovery pass. Preserve artifacts and failures for review.

The preload and daemon-task cancellation fixture in steps 2–5 remain to be
built and independently qualified. The commands above are available today;
the full-daemon matrix is a reproducible design, not an implemented test claim.

Other limits remain: dispatch tests intentionally wait for the monitor/renewal
abort before releasing the barrier. They do not establish immediate prevention
between durable cancellation/attempt/scope/revocation and its observation, or
linearizability of a filesystem/external effect against revocation. Lease loss
after claim is observed on the actual renewal cadence, not immediately. No test
interrupts SQLite commit/fsync, races machine power failure, covers every
instruction boundary, or establishes remote idempotency. No new assertion
closes forged-receipt, arbitrary network-effect, or independent-review gaps.
