# GE-04 — independent supervisor trust configuration prototype

**SECURITY HOLD — isolated test fixture only, no production admission or helper execution.**

`experiments/ge04/supervisor-trust-config.py` loads `trust.json` (`version`, `trustedKeySha256`, `release`) from a separate owner-checked, non-group/other-writable configuration directory, using a pinned directory descriptor and `O_NOFOLLOW` for the file. It reuses the signed-installation reader's inode checks and requires the installed release public key to match the configured SHA-256 digest before signature and helper verification. This moves the pin out of the release directory for the experiment. `test-supervisor-trust-config.py` exercises valid configuration, writable config/file, symlink substitution, and release-key substitution denial. Privileged CI additionally creates a root-owned config directory and checks a real UID 65534 worker cannot overwrite the config or create a replacement. CI confirmation of this revision is pending.

**Not a production trust anchor:** the function still takes caller-selected configuration/installation paths and a test-only owner UID override. A same-UID attacker who can modify the config can replace the pin and the signing key together. No ancestor directory validation, mount trust, atomic generation, or rollback floor is implemented; `Path.resolve()` is not a security primitive. Production must hardcode a root-owned configuration location in the trusted supervisor, pin directory ancestry, restrict supervisor capabilities, and use an independently approved signing-key lifecycle. No automatic replay or mutation is authorized.
