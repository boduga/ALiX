# GE-04 — signed release and root-owned installation experiment

**SECURITY HOLD. No production integration, admission, helper execution, or merge.**

`experiments/ge04/signed-release.py` is a standalone Ed25519 verification fixture (`cryptography` dependency) for an exact signed release envelope (`version`, `release`, `platform`, `helperSha256`). It verifies the signature against an independently supplied 32-byte Ed25519 public key, requires the expected release identifier and Linux platform, then hashes helper bytes against the signed digest. The test `python3 -B experiments/ge04/test-signed-release.py` generates ephemeral trusted/attacker keys and rejects attacker signatures, changed manifest, changed helper and wrong release. **This does not install a production trust anchor:** the CLI accepts a caller-selected public-key path and reads paths without pinned descriptors; a malicious caller can supply its own key and manifest. Only a privileged supervisor with an administrator-provisioned, pinned key can make signature verification authoritative.

`experiments/ge04/test-signed-release-root.py` is a root-gated Linux test (fails without root; never elevates itself). It creates a temporary root-owned 0755 installation with 0444 key, manifest, signature and helper files; forks a real UID/GID 65534 worker and proves denial of file overwrite and new-file creation. The GE-04 privileged CI job installs a pinned test-only `cryptography==43.0.3` into an isolated Python 3.12 environment and requires an explicit PASS marker. **The test uses ephemeral keys and a temporary installation, not a trusted build release.** Local unprivileged runs do not qualify the root gate; a successful GitHub CI run is required.

Outstanding: release signing key custody and independent build attestation; supervisor-pinned trust anchor and fixed root-owned installation path; descriptor-based manifest/signature/key loading with ancestor validation and atomic deployment; rollback/version floor; kernel-bound child identity; authenticated coordinator admission, lease fencing, durable receipts, crash reconciliation. The signed-release verifier is intentionally not wired into `supervisor-manifest.py` or production. The existing pre-spawn record remains `NOT_AUTHORIZED`.
