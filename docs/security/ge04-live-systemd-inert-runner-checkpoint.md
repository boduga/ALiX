# GE-04 live systemd lifecycle validation — disposable CI runner only

**GE-04 SECURITY HOLD active. No production deployment, mutation authority, service enablement, or PR merge.**

The prior GE-04 prototype checked a unit file with `systemd-analyze verify` but did **not** exercise a live systemd manager. `experiments/ge04/test-live-systemd-inert-root.py` adds a strictly opt-in, root-only test for a disposable GitHub Actions Ubuntu runner. The `ge04-live-systemd-inert` job is scoped to PRs from `feat/ge04-linux-backend-adapter`; it requires both `CI=true` and `ALIX_GE04_EPHEMERAL_SYSTEMD_TEST=1`, an available systemd manager, and absence of every intended temporary unit/install/config/state/runtime path before writing anything. The test refuses to replace existing installations. It never enables a service or edits `/etc/systemd/system`.

The test creates a **transient unit file in `/run/systemd/system`**, a root-owned protected *inert* installation under `/opt/alix/ge04`, protected startup config under `/etc/alix-ge04-inert`, and protected authority state under `/var/lib/alix-ge04-inert`. Systemd creates the `RuntimeDirectory=/run/alix-ge04-inert`; its mode is `0711` (traversable by untrusted UID 65534, not writable), while the state directory is `0700`. This corrects the initial static prototype's `0700` runtime mode, which would have blocked an untrusted client from traversing to the intentionally sendable inert socket. `RuntimeDirectoryPreserve=yes` deliberately retains the orphan endpoint so a second explicit start can prove stale-endpoint refusal; it is **not** a production recovery policy.

The privileged regression drops an independently executed coordinator to UID/GID 65534 and checks that it cannot modify code, bootstrap, or authority state. It starts the service through the **real systemd manager**, waits for its fixed inert AF_UNIX socket, sends one kernel-attested message, and verifies a consumed fixture approval and unverified inert observation. It then resets the test-only start rate limit and attempts a second start: an orphan endpoint must prevent fresh execution. It checks that `NRestarts=0` and the approval is not reset. A `finally` block stops and resets the service, deletes the temporary unit, reloads systemd, and removes test-created paths. On failure it reports systemd status and recent unit journal entries.

This test was added to the isolated GitHub-runner CI job. Local machine verification covers syntax, static unit policy, and `systemd-analyze verify` only; **a live manager pass cannot be claimed until CI reports success**. Even a live CI pass does not validate deployment service ownership, power-loss recovery, delegated privilege, production sandbox compatibility, actual OS mutation-boundary authorization, trustworthy effect receipts, or independent review. The experimental systemd unit remains non-installable (no `[Install]`) and no release gate is lifted.
