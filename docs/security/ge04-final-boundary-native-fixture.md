# GE-04 — First kernel-effect fixture under final-boundary exclusion

**SECURITY HOLD: privileged *test-only* kernel create, NOT production mutation authority.** This experiment must not be installed or connected to `createScopedMutationService`; PR #1039 stays open and unmerged.

`experiments/ge04/final-boundary-inert-kernel-create.c` is a small Linux-only native fixture that creates **one fixed filename with fixed innocuous bytes** using an inherited, pre-pinned directory FD and `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS)`. It uses `O_CREAT|O_EXCL`, then fsyncs file and directory. It has no arbitrary-path, arbitrary-content, delete, replace, shell, or production tool interface. The C binary is compiled into an isolated temporary directory only for testing.

`experiments/ge04/test-final-boundary-kernel-root.py` is the privileged Linux regression. Its root-only harness builds the native binary in a disposable root-owned tree, creates a SUP-25 protected authority fixture, enters that fixture's exclusive lock, checks an exact known fixed approval/lease/policy/expiry state, and durably persists one PREPARED/inFlight consumption **before** calling the kernel helper. It keeps the lock until the helper terminates or raises. It checks a successful kernel write and single-use approval; a helper that fsyncs an actual file then exits 86 without terminal confirmation must leave inFlight quarantined and deny replay. A deterministic parent-directory rename and symlink substitution *after opening the directory FD* must leave an external sentinel unchanged; the write must land in the pinned renamed directory. A subprocess dropped to UID/GID 65534 must fail to rewrite protected authority state and the effect file. The test is added to privileged GE-04 CI.

## Precisely bounded evidence

- Real kernel `openat2` containment via a pinned FD, one fixed create and fsync, plus the native process exit/notification behavior, are exercised.
- The supervisor-side Python test holds one cooperative `flock` while it synchronously invokes the helper. Explicit `SUP-25` fixture revocation follows that lock, but **there is no proof that every production policy publisher, approver, revoker or worker participates**.
- The test does **not** establish a trustworthy production approval or signed release, independent production supervisor-owned key, trusted monotonic clock, synchronous policy publication protocol, full request parsing, secure transfer of arbitrary authorized bytes, or a native effect receipt. The helper's fixed stdout marker is untrusted terminal observation only.
- A compromised privileged launcher/root actor can substitute the test binary, state, parent FD or record; the attacker's root-equivalent capabilities remain outside this narrow distinct-UID demonstration. The SUP-27 same-UID forgery findings still apply to any unprotected fixture.
- The test runs on temporary directories with an already-available parent; it does not cover nested parent creation, existing-target idempotency, replace/delete, hardlink/bind-mount semantics, power cut, disk corruption, atomic multi-file changes, malicious userns/mountns, or executable pinning against root attackers.
- A real effect can precede a missing terminal marker. The test intentionally returns `GE04_REAL_KERNEL_EFFECT_UNCERTAIN_NO_RETRY` and does **not** automatically reconcile it to success despite being able to observe the test file. This is required until authenticated durable effect evidence is implemented.
- A successful test remains **unverified**. No module is added to the production service registry and `UnavailableScopedMutationService` remains unchanged.

The next security steps are an independently authenticated effect/receipt design, durable crash reconciliation with fault injection, complete operation-policy publication under the same enforced domain, and independent review. Passing this checkpoint is **not** release authorization.
