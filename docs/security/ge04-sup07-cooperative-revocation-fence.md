# GE-04 SUP-07 — Cooperative cross-process revocation fence experiment

**SECURITY HOLD. Isolated harmless process/marker fixture only. This is not production authorization or a qualified mutation fence.**

`experiments/ge04/cooperative-revocation-fence.py` serializes simulated mutation admission and lease/policy revocation through the same `flock` on a stable file. It reads the fixture policy/lease state while holding that lock, rejects stale policy revisions, explicit revocation, uncertain in-flight state and expired leases (according to the caller-supplied fixture time), then persists `inFlight` before a harmless marker action. The lock is held across the marker and until a durable state update. An independent revoker waits for the lock and publishes a new policy revision plus `revoked` only after the prior action releases it. A crash leaves `inFlight` durable; later revocation classifies this `uncertain` rather than assuming no mutation or permitting replay.

`experiments/ge04/test-cooperative-revocation-fence.py` tests independent processes and both lock-winning orders, checks that revocation waits for the in-flight fixture, verifies expiry and revision mismatch denial, and checks that a crash after pre-action persistence leaves an uncertain quarantine state. CI runs the unprivileged Linux fixture.

**Limitations:** The lock is cooperative and may be bypassed by nonparticipating writers or revokers. The caller supplies the root, lease/policy state and clock: no authenticated coordinator, cross-process trust root, OS-enforced worker isolation, signed state publication, atomic approval consumption, secure expiration source, protected operation descriptor, or kernel fd-relative mutation is involved. The sample path open validates only the final directory; untrusted ancestors and same-UID replacements can break the safety assumption. Host crash releases `flock`, and the fixture does not constrain orphaned helpers. `fsync` does not prove power-loss persistence on arbitrary storage. The marker is an inert diagnostic file, not a mutation receipt. This experiment is not connected to SUP-05/SUP-06 nor to production `UnavailableScopedMutationService`.

**Next gate:** Specify and test an independently authenticated coordinator/supervisor boundary with one shared policy/lease revision authority and operation-specific fd-relative execution. Analyze power loss and coordinator/helper crashes, including orphan processes and lease expiration during mutation. Do not merge PR #1039 or lift SECURITY HOLD.
