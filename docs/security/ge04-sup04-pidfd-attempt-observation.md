# GE-04 SUP-04 — pidfd-bound, attempt-reserved unverified observation experiment

**SECURITY HOLD. Isolated harmless Linux fixture only. No helper execution, approval, authenticated receipt, mutation, or production integration.**

`experiments/ge04/pidfd-attempt-observation.c` demonstrates that one native parent can retain the kernel pidfd returned atomically by `clone3(CLONE_PIDFD)` while observing a harmless child via `waitid(P_PIDFD)` and writing a durable, attempt-named observation. The existing pre-spawn inode must exist and pass owner/mode/single-link/stability checks. Before creating any child, the parent writes an exclusive, fsynced `<attempt>.pidfd-started` reservation. A duplicate attempt fails before spawning, including concurrent contenders. After observing a verified kernel child exit, the **same parent process holding the pidfd** exclusively writes `<attempt>.pidfd-unverified`, fsyncs the file and directory, and closes the pidfd. The result is always `*_UNVERIFIED`; PID and text are never accepted as mutation success or authority.

`test-pidfd-attempt-observation.py` compiles and runs harmless native fixtures for zero exit, nonzero exit, SIGKILL through pidfd, forged stdout, invalid/unknown attempt, two concurrent supervisors contesting a single attempt, unavailable clone3, and supervisor exit after observing the child but before persisting evidence. It verifies a crash leaves the durable reservation with no terminal observation, and cannot silently reuse that attempt. The dedicated GE-04 CI job runs the fixture. No system write operations are performed by the child.

**Security limitations:** The caller still chooses the test paths, process and UID; there is no privileged supervisor bootstrap, trusted ancestor/mount pinning, signed executable handoff, worker credential separation, coordinator authorization, lease/policy revocation fence, or authenticated terminal receipts. The C pre-spawn reader checks file metadata but does **not** independently validate the strict pre-spawn JSON schema or authenticate its origin; a same-UID attacker can fabricate fixture input. The observational file is intentionally a separate untrusted record format rather than a SUP-03 authenticated receipt. The existing ledger inventory treats these new file names as **UNCERTAIN**. Cross-process operator recovery, fsync crash/power-loss qualification, and worker-proof integrity are not established. A retained pidfd proves child identity to its owning supervisor only, not whether a filesystem mutation was durably committed.

An orphaned reservation is permanently quarantined in this experiment; it cannot be retried as an authorized operation. Production `UnavailableScopedMutationService` remains unchanged. Do not merge or enable GE-04.
