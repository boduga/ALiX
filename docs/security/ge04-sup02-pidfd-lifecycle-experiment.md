# GE-04 SUP-02 — atomic pidfd child lifecycle experiment

**SECURITY HOLD — isolated Linux process experiment only. No GE-04 helper launch, authorization, trusted receipt, or production integration.**

`experiments/ge04/clone3-pidfd-probe.c` uses Linux `clone3(CLONE_PIDFD)` to create a harmless child and obtain its kernel-bound pidfd *as part of child creation*, avoiding the separate `spawn()` → `pidfd_open()` identity window. The parent uses pidfd polling and `waitid(P_PIDFD)` to observe exit status. In the SIGKILL fixture it sends the signal via `pidfd_send_signal`, not a reusable numeric PID. Failure of `clone3` or absence of the pidfd fails closed; no fallback to numeric PID identity is allowed. The fixture reaps children and closes pidfds, using a bounded poll and kill/reap cleanup on failure.

`experiments/ge04/test-clone3-pidfd-lifecycle.py` compiles the isolated C fixture and checks normal exit, early exit, nonzero exit, SIGKILL, invalid identity rejection, unsupported-path failure, unknown mode rejection and forged stdout. In the forged case a child prints a line resembling a GE-04 fsync notification, but the only output classification remains `PROCESS_EXIT_ZERO_UNVERIFIED`. This test runs in the GE-04 branch-only security CI lane; any unavailable `clone3` primitive makes the test fail rather than silently downgrade.

**What this does not prove:** The child is a harmless inline test branch, not the signed/sealed native helper. There is no trusted supervisor bootstrap, protected IPC or credential/UID boundary, authenticated child-to-supervisor receipt, approval/lease/policy fence, durable state transition, crash reconciliation, parent-lifetime guarantee, successful filesystem mutation, or production execution. `waitid` and pidfd indicate process lifecycle only; they cannot by themselves prove durable file outcomes. SIGKILL and PIDFD lifecycle tests do not establish atomic mutation authority. Keep production `UnavailableScopedMutationService` unchanged, PR #1039 unmerged and SECURITY HOLD active.
