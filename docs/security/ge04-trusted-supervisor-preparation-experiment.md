# GE-04 — composed trusted supervisor preparation experiment

**SECURITY HOLD. No authorization, execution, production integration, receipt, or automatic replay.**

`experiments/ge04/trusted-supervisor-preparation.py` composes existing root-to-leaf no-symlink descriptor verification, a separately stored signing-key pin, signed release identity and signed sequence checked against a protected rollback floor, and a conservative read-only supervisor evidence audit. The release verifier can now optionally return the **exact bytes it authenticated** from its pinned release-directory FD, without reopening the helper pathname. The preparation prototype copies these bytes into a Linux `memfd`, independently hashes the copy, applies and verifies write/grow/shrink/seal seals, then rechecks the evidence inventory. The caller must close the returned FD. There is no launch path in this module.

Preparation deliberately requires a signed monotonic release sequence and a protected rollback floor. Empty evidence is the only accepted inventory: any prior pre-spawn/denial entry, unknown entry, or malformed state causes fail-closed rejection. **An empty evidence directory is not authorization.** The inventory read is not a cross-process atomic lock, so the recheck is a defensive observation only, not safe admission. This prototype cannot be used to authorize execution or replay.

`test-trusted-supervisor-preparation-root.py` runs in the dedicated privileged GE-04 CI job; it checks sealed signed bytes, write rejection, below-floor downgrade rejection, uncertain evidence rejection, and tampered signed helper rejection. It must not be reported as passed locally on an unprivileged host. All paths, the owner UID and trusted configuration remain fixture-selected. Production needs an administrator-fixed supervisor bootstrap, controlled atomic generation and floor advancement, pidfd-bound child identity, cross-process policy/lease fencing, protected durable terminal receipts, crash qualification and independent security review. Leave `UnavailableScopedMutationService` unchanged and PR #1039 unmerged.
