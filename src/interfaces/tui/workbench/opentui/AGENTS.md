# OpenTUI Workbench renderer

## Purpose

Build the native OpenTUI renderer from renderer-neutral `WorkbenchViewState` while the ANSI canvas remains the default.

## Ownership

- `workbench-layout.ts` mounts retained native region nodes and maps shared Workbench surface geometry to their positions. Its caller owns renderer creation, input, and teardown.
- `workbench-content.ts` mounts retained operator-shell header/footer, agent-roster, transcript, inspector, composer, task/artifact drawer, and approval-card content in the layout regions; it consumes the assembled view state and owns no runtime projection. It owns the native preview palette, styled text, and bounded pane copy.
- `input.ts` normalizes native OpenTUI key and paste events into the shared Workbench vocabulary and routes them through `routeWorkbenchInput`; it maps to typed intents and owns no terminal I/O.
- `host.ts` mounts the retained layout and content on a native renderer, subscribes to key/paste/mouse/resize events, and forwards keys, paste, and typed click actions to caller-supplied callbacks (the controller owns routing). It exposes `update()` for the controller to push each frame and repaints on resize; it owns no store, runtime ports, or terminal lifecycle (raw mode, restore) beyond the renderer it is given.

## Local Contracts

- Consume `WorkbenchViewState` and shared `layoutWorkbenchSurface` geometry for presentation, including display-cell wrapping of composer text; derive no runtime facts or operator decisions inside native nodes.
- Keep region nodes stable across updates and resize. Hide zero-size or absent regions, and paint an overlay above the transcript when geometry calls for one.
- Native agent-roster content preserves unavailable snapshots, run identity, selected-agent visibility, and source task labels. Native transcript content uses existing category, selected-agent, and details-mode state. **Assistant and user prose renders as markdown through the shared `renderResponse` (`../../blocks/render.ts`)** — the same parser/layout the ANSI transcript uses, so there is one markdown implementation, not a second divergent one; `ansiRowToNativeParts` maps its SGR runs, including preview truecolor sequences, onto the native palette. Never print raw markdown (`**bold**`, a `|---|` table separator) into the transcript. Row labels use **local** wall-clock `HH:MM:SS` (never `toISOString()`'s UTC), and the actor gutter stays tight so prose begins near its responder. Tool cards paint without the `│├─`/`│└─` connector guide and align with response prose; the actor gutter is applied ONCE per row (never per styled run, which would insert spaces inside the row and break its column math). Arrow keys, PageUp/PageDown, and wheel events over the transcript scroll by presentation rows; End resumes follow. The content renderer reports its clamped row distance to the CLI host after each frame so extra Up presses at the top never delay Down. Paused follow retains the last conversation snapshot as its semantic anchor through append, filter, and resize. Native inspector content renders the shared bounded sections, and native composer content renders the wrapped draft with its placeholder and hidden-row indicator. All clip to the current region; content updates follow layout updates after resize. Drawer content routes by the active drawer — agents, tasks, or artifacts — through the shared selectors, and the same body paints in the wide side pane or the narrow overlay. Header and footer render the operator-shell snapshot. The native header mirrors the canonical three-row ANSI band: row 0 carries the brand, badge and the right-aligned `workspace · mode · approval/stall warnings · session-roster` groups in that precedence, row 1 carries the top status line, row 2 stays reserved blank. Both renderers build that status line from the single exported `buildOperatorStatusSegments`, mapping tone to escapes (ANSI) or palette colors (native); a renderer never restates the status text. Under width pressure row 0 keeps mode and drops optional groups from the right. The footer shows shortcuts and counters. Authoritative pending approvals stack as bounded cards above every region, appearing and clearing only with the supplied view state. Task-state glyphs, byte sizing, and coordination lines come from `../model/display-format.ts`, shared with the ANSI drawer.
- Native tool cards own their single tool-name row. Preserve the shared card's cyan-background `TOOL` badge through truecolor foreground/background conversion; never add a duplicate native heading above the card.
- The native preview visual uses a near-black background, cyan pane borders and headings, muted supporting text, state colors, a selected-row fill, and interior headings rather than border titles. The transcript toolbar shares its heading row when width allows. Retain text labels with colors. Preserve workspace facts, timestamps, toolbar state, and tool metadata from `WorkbenchViewState`; never seed live panes from mockup strings.
- The header uses terminal bold for the cyan `ALiX WORKBENCH` brand and cyan for the workspace path; the preview badge and labels stay muted, and agent counts use green. Font family and cell size belong to the terminal emulator, so native content cannot enlarge only the brand.
- Left clicks select visible agent, task, and artifact rows in wide panes or narrow drawers; expand the roster, open coordination entry or inspector/artifact inspection, focus transcript/composer, activate transcript filters/follow, and activate every advertised footer hint. Hit targets are emitted by the same builder that paints the rows, labels and segments they cover — `BoundedLines` carries one action per row, the footer derives targets from its own hint list, approval targets come from `workbenchApprovalDecisionSpans`, and inspector rows take their action from the shared section that produced them. A hit target never re-derives identity from painted string literals or a positional row counter. Inspector section headings are structure, not controls, and carry no action. Every authoritative approval card keeps the shared decision row and each label resolves the approval that card names; clicks on panes covered by an approval card stay blocked while the card itself stays actionable. Ignore right clicks, drags, and hidden rows. The host wires every clickable region through one path; the host emits typed actions and `TuiApp` validates agent, task, artifact, and approval identity against the current snapshot before acting.
- A selected OpenTUI CLI process owns the terminal through its native renderer (`createCliRenderer` in `lifecycle.ts`) and launches only on an interactive TTY; the launcher supplies `--experimental-ffi`. Native key events normalize to the exact `routeWorkbenchInput` vocabulary — `Ctrl+<letter>`, named navigation/edit keys, `Shift+Enter`/`Shift+Tab`, and printable graphemes taken from the key sequence; OS-owned modifier combos and key releases are dropped. Bracketed paste decodes bytes to text for the authoritative cursor. Native and ANSI renderers never own one terminal together.
- Keep `@opentui/core` and its `web-tree-sitter` peer pinned to the runtime-tested versions. Only the launcher supplies `--experimental-ffi` for selected OpenTUI CLI use.
