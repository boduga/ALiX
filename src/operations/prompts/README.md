# Prompt Registry

## Overview
Central, auditable inventory of every static model-facing prompt in ALiX: stable ids, versions, owning source files, and the prompt text itself. It intentionally excludes dynamic per-turn assembly (tool manifests, memory blocks, digests), which belongs to the builders that produce them. The registry exists so prompt-surface audits, per-layer token accounting, and snapshot tests can fail loudly when prompt text changes without a version bump.

## Interface
- `PromptEntry`: `{ id, version, source, text }`, where `source` names the file that owns the registered text [registry.ts:PromptEntry].
- `PROMPT_REGISTRY`: the exported `PromptEntry[]` covering agent system/supplement/shell/read-only prompts, six subagent roles, the planner graph prompt, and the external-retrieval route prompt [registry.ts:PROMPT_REGISTRY].
- Registered id families: `agent.system-base`, `agent.research-supplement`, `agent.execution-supplement`, `agent.verification-supplement`, `agent.shell-task`, `agent.read-only-mode`, `subagent.explorer`, `subagent.reviewer`, `subagent.test-investigator`, `subagent.docs-researcher`, `subagent.worker`, `subagent.researcher`, `planner.graph`, `route.retrieval-system` [registry.ts:PROMPT_REGISTRY].
- `entry(id, version, source, text)`: private constructor helper that shapes each record [registry.ts:entry].

## Invariants
- Every registered prompt carries both a stable id and an explicit version; versions range `1.0.0`–`1.3.1` for agent prompts and `2.7.0` for `planner.graph` [registry.ts:PROMPT_REGISTRY].
- Registered text is imported from its owning module — `system-prompt.ts`, `agent-registry.ts`, `graph-planner.ts`, `route-prompts.ts` — never duplicated inline in the registry [registry.ts:PROMPT_REGISTRY].
- `planner.graph` is generated by calling `buildPlanPrompt()` at registry-construction time, not stored as a literal [registry.ts:PROMPT_REGISTRY].
- `route.retrieval-system` registers only the `.systemPrompt` field returned by `buildExternalRetrievalPrompt("external_retrieval")` [registry.ts:PROMPT_REGISTRY].
- Per-tier model variants belong here as new ids rather than inline branches in prompt builders [AGENTS.md:Local Contracts].

## Side Effects
- Module evaluation calls `buildPlanPrompt()` and `buildExternalRetrievalPrompt("external_retrieval")` once to materialize registry entries [registry.ts:PROMPT_REGISTRY].
- No file, network, or process I/O; the registry is an in-memory array of strings [registry.ts:PROMPT_REGISTRY].
