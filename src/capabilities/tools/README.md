# Model Tool Surface

## Overview
The model-callable tool surface: a single capability catalogue, an executor that composes authorization with dispatch, family routers that resolve an already-authorized call to a filesystem or store operation, and the individual tool implementations. Every call follows the same path — repair, hash, policy/ownership authorization, single-use approval claim, effect journal, router dispatch, then `ToolResult` rendering.

## Invariants
- The registry is the single tool/capability catalogue: each entry pairs an internal executor ID with its capability id, policy key, risk, domain, `mutates`, and `alwaysInclude`; display and adapter layers derive from `createToolCapabilityRegistry` instead of keeping a parallel taxonomy [tool-registry.ts:createToolCapabilityRegistry]
- A tool absent from `ALIX_BUILTIN_EXECUTORS` has no model-facing name and no type that admits it; `ToolName` derives from the manifest union rather than a hand list [types.ts:ToolName]
- `ToolExecutor` is value-imported only by `tool-executor-factory.ts`; every composition site constructs through `createToolExecutor` [tool-executor-factory.ts:createToolExecutor]
- Dispatch order is fixed: tool repair, argument hash, requested event, mutation-path constraint, authorization, single-use claim, started event, effect journal, router dispatch, terminal receipt [executor.ts:dispatch]
- Authorization composes `PolicyGate` and `OwnershipGate` through `ExecutionAuthorization`; a `denied` decision returns `{ kind: "denied" }` without running any router [executor.ts:dispatch]
- An `approval_required` decision persists a continuation and returns a structured `approvalRequired` pause that must not emit a terminal span [executor.ts:isPreApprovalDenial]
- A cited approval is claimed exactly once, before any router runs; a concurrent or fresh-process replay loses the race and is denied rather than executed [executor.ts:claimApproval]
- A `continuation-resume` request must carry an `approvalId` that is present, `approved`, and unexpired; a caller-set `source` string alone is never authorization [executor.ts:dispatch]
- Continuation resumes re-run mandatory denies with `sessionMode: "bypass"` so hard denies still fire even though a durable approval is valid [executor.ts:mandatoryContinuationDeny]
- An `outcomeUnknown` result records no execution receipt on either dispatch route, leaving the claim `pending` and later classified `unverified`; a thrown router exception is treated as uncertain [types.ts:ToolResult]
- The effect journal applies only to registry entries with `mutates` and `risk` of `high` or `critical`, excluding safe-shell commands; a replay of a claimed effect is blocked until reconciled [effect-journal.ts:requiresEffectJournal]
- Durable effect-journal execution rejects unsupported hosts before adapter entry, so a non-Linux host fails closed rather than applying an unjournaled effect [effect-journal.ts:executeWithEffectJournal]
- Containment belongs to `WorkspacePathResolver`: `ToolExecutor.execute()` checks every path argument before dispatch, and routers must not add a hand-rolled `relative`/`startsWith` substitute [executor.ts:execute]
- Owned-scope writes and deletes both call `isWithinOwnedScope` through `isOwnedWriteTarget`; a new file outside declared ownership is denied, not silently created [tool-router.ts:isOwnedWriteTarget]
- Safe-shell admission classifies command shape only; every filesystem operand is still validated through the same workspace/canonical-path boundary as file tools [tool-router.ts:ShellToolRouter]
- Shell execution enforces the same domain allowlist, DNS resolution, and private-address rejection as `alix_web_fetch`, so `curl`/`wget`/`ssh` cannot bypass SSRF controls; command substitution in a network invocation fails closed [shell-network-policy.ts:validateShellNetworkCommand]
- Patch syntax is authoritative: a `*** Begin Patch` payload with bare `@@` markers is normalized to exact search/replace blocks even when labeled otherwise, and a parse yielding zero hunks is a rejection [tool-router.ts:PatchToolRouter]
- A non-zero shell exit is an error with `outcomeUnknown`, never success and never a retryable failure; a real signal is distinguished from a plain non-zero code [shell-tool.ts:runCommand]
- `toolResultText` preserves every success payload family — `output`, `content`, `value`, `matches[]`, `exists` — so a search result is never rendered as empty [result-text.ts:toolResultText]
- `emitToolTelemetry` swallows every append failure so telemetry can never turn a successful tool into a failure [telemetry.ts:emitToolTelemetry]
- All workspace walks share `IGNORED_DIRS` and the root `.gitignore` subset, and a directory pattern also covers its contents [ignore.ts:isIgnoredPath]
- `walkWorkspaceFiles` fails closed when the requested subdirectory escapes the workspace, never follows symlinks, and is bounded by the caller's early exit [file-tools.ts:walkWorkspaceFiles]
- `hashArgs` sorts object keys at every depth so the same logical arguments always produce the same digest [hash-args.ts:hashArgs]
- `fetchPinned` validates the initial hostname and every redirect, pinning the socket lookup to the addresses it resolved so DNS rebinding cannot redirect the connection [web-fetch.ts:fetchPinned]
- `stripHtml` lifts JSON-LD article fields before removing scripts and keeps the recovered text delimited as untrusted fetched data [web-fetch.ts:stripHtml]
- Web search treats an unconfigured, unreachable, errored, or engine-degraded SearXNG as a degraded backend and falls back to Brave; a genuine empty response is returned as-is [web-search.ts:webSearchTool]
- `state.query` is read-only, requires one of the fixed `STATE_QUERY_KINDS`, and clamps `limit` to 50 [state-query.ts:handleStateQuery]
- `tryHandleStateProposal` intercepts only the state-proposal tool, only when the SEND gate is enabled and an emitter exists, and never throws [state-proposal-tool.ts:tryHandleStateProposal]
- Collaboration tools bind run/worker identity from the injected `WorkerCollaborationAPI`; the model cannot pass `runId`, `workerId`, `attempt`, or a storage path [collaboration-tools.ts:createCollaborationTools]
- A bound collaboration handler is authorized through `authorizeBoundTool` before it runs: allow executes, ask waits for durable approval, deny returns access denied [executor.ts:authorizeBoundTool]
- Routing is a decorator chain: `ToolAwareRouter` filters by intent without changing authorization, and `CompositeToolRouter` selects the first router that `canHandle` the name [tool-router.ts:CompositeToolRouter]

## Side Effects
- Appends `tool.requested`/`tool.started`/`tool.output`/`tool.completed`/`tool.failed` events and an `observability.metric` row through the fail-open `logEvent` path [executor.ts:logEvent]
- Persists a continuation record under the workspace for an approval-required call [executor.ts:dispatch]
- Claims and later reports a durable approval outcome, leaving a crash between claim and execution `pending` [executor.ts:recordApprovalOutcome]
- Creates parent directories and writes files with exclusive-create plus staged-replace semantics; `file.delete` removes the target only [tool-router.ts:FileToolRouter]
- Creates a patch checkpoint before applying and restores it when application fails [tool-router.ts:PatchToolRouter]
- Spawns one fresh OS process per `shell.run` with stdin ignored, killing the process tree on operator abort [shell-tool.ts:spawnCommand]
- Writes and fsyncs effect-journal records under the workspace ledger and takes the approval-store lock for each journaled effect [effect-journal.ts:executeWithEffectJournal]
- Writes notification JSON under `~/.alix/notifications` and delivered files under `~/.alix/user-files` [misc-tools.ts:sendNotification]
- Issues outbound HTTP(S) only after domain and address validation, with a 15 s default timeout and a 1 MB default byte cap [web-fetch.ts:fetchPinned]
- Queries SearXNG or the Brave API over the network and reads the Brave key from the credential store [web-search.ts:webSearchTool]
- Reads workspace files, session records, the unified audit log, the approval store, the daemon task registry, and the schedule store for `state.query`; nothing is written [state-query.ts:handleStateQuery]
- Appends a validated execution-state patch through the emitter and returns committed or the rejection reason [state-proposal-tool.ts:executeStateProposal]
- Pure helpers — `toolResultText`, `hashArgs`, `inferCapability`, `canonicalCapabilityOf`, `isIgnoredPath`, `isSafeShellCommand`, `safeShellPathOperands`, `isPrivateNetworkAddress`, `normalizeNumericHost` — perform no I/O [result-text.ts:toolResultText]
