# Learning (`src/planning/learning`)

## Overview
The learning subsystem turns observed outcomes into reviewable calibration suggestions and provenance records. Its governing rule is stated in `learning-types.ts`: learning proposes, governance approves — the artifacts here are data objects and append-only records, never applied mutations. Calibration adapters read existing stores (`OutcomeStore`, `RiskScoreStore`, `GovernanceReviewStore`) and hand pure builders the observations they need; `runLearningRefresh` is the single writer that persists the resulting signals, profiles, and summary report to `LearningStore`. A second, separate concern in the same directory is the P11.4 confidence engine, which compares baseline and current subsystem scores against a strategic plan and emits a bounded confidence model.

## Invariants
- Adapters never write learning state: they return `AdapterResult` and `runLearningRefresh` is the only `LearningStore` writer [learning-refresh.ts:runLearningRefresh], [adapter-diagnostics.ts:CalibrationAdapter].
- All artifacts from one refresh share a single `generatedAt`, and run identity is `refresh:<generatedAt>` so a run is reconstructable from artifacts alone [learning-refresh.ts:runLearningRefresh], [learning-refresh.ts:RunLearningRefreshResult].
- Refresh is append-only and not idempotent: repeating with the same `generatedAt` appends another report row by design [learning-refresh.ts:runLearningRefresh].
- Writes are best-effort per artifact: a failed append is logged and does not abort the remaining appends or the run [learning-refresh.ts:runLearningRefresh].
- `opts.adapter` accepts only `recommendation`, `risk`, `governance`, or `all`; anything else throws before any adapter runs [learning-refresh.ts:runLearningRefresh].
- Both sides of each cross-store window join use the same `generatedAt` and `windowDays`, so results do not drift with the wall clock [risk-calibration-adapter.ts:RiskCalibrationAdapter], [governance-calibration-adapter.ts:GovernanceCalibrationAdapter].
- Risk join is `risk.id.replace(/^risk-/, "")` matched to the newest `OutcomeRecord.subjectId`; unmatched risks count as `noOutcome` [risk-calibration-adapter.ts:RiskCalibrationAdapter].
- Governance join is `review.proposalId` → `outcome.subjectId`; `concernsRaised` is inferred (1 for `agree_with_concerns`/`challenge`, else 0) and the adapter reports `fidelity: "low"` [governance-lens-observation-builder.ts:buildLensObservations], [governance-calibration-adapter.ts:GovernanceCalibrationAdapter].
- Recommendation bucketing excludes outcomes whose `confidence` is `undefined` or `null` and counts them as `missingConfidence` [recommendation-calibration-adapter.ts:RecommendationCalibrationAdapter].
- Builders are pure: no I/O, no store access, no mutation; a builder emits suggestions only, never applies them [recommendation-calibration-builder.ts:RecommendationCalibrationBuilder], [risk-calibration-builder.ts:RiskCalibrationBuilder], [governance-calibration-builder.ts:GovernanceCalibrationBuilder], [routing-calibration-builder.ts:RoutingCalibrationBuilder].
- Builder thresholds are constructor defaults, not hardcoded call sites: min samples 5 / delta 0.1 [recommendation-calibration-builder.ts:RecommendationCalibrationBuilder], high 0.7 / low 0.3 / min 3 / rate 0.3 [risk-calibration-builder.ts:RiskCalibrationBuilder], min reviews 5 / high PV 0.7 / low PV 0.5 / FP 0.4 / miss 0.3 [governance-calibration-builder.ts:GovernanceCalibrationBuilder], min count 5 / quality delta 0.15 / cost delta 0.25 / latency 5000ms [routing-calibration-builder.ts:RoutingCalibrationBuilder].
- Suggested values are clamped rather than unbounded: recommendation multiplier `[0.5, 1.5]` [recommendation-calibration-builder.ts:RecommendationCalibrationBuilder], risk weight `[0.3, 0.9]` [risk-calibration-builder.ts:RiskCalibrationBuilder], governance lens weight `[0.3, 1.5]` [governance-calibration-builder.ts:GovernanceCalibrationBuilder], routing preference `[0.3, 1.5]` [routing-calibration-builder.ts:RoutingCalibrationBuilder].
- Routing calibration is observational only and returns empty for sparse or non-comparative data — absence of signals means insufficient data, not a clean result [routing-calibration-builder.ts:RoutingCalibrationBuilder].
- `LearningStore` is append-only: it exposes no update, delete, clear, or truncate primitive, and corrupt JSONL lines are skipped rather than failing the read [learning-store.ts:LearningStore].
- Generated IDs are filled only when missing; caller-supplied `id` and `generatedAt` are preserved [learning-store.ts:LearningStore], [evidence-chain-store.ts:EvidenceChainStore].
- `EvidenceChainStore` likewise exposes only `appendChain` as a mutation primitive; there is no update/delete/replace path [evidence-chain-store.ts:EvidenceChainStore].
- `ConfidenceModelStore.save` validates before writing, so an invalid model is rejected before any file or directory is created [confidence-model-store.ts:ConfidenceModelStore].
- Confidence updates are bounded by `DEFAULT_LEARNING_CONFIG`: ±0.05 per cycle, confidence clamped to `[0.05, 0.95]`, minimum improvement delta 5, 7-day evaluation window [learning-config.ts:DEFAULT_LEARNING_CONFIG], [learning-types.ts:ConfidenceUpdate].
- `buildConfidenceModel` validates plan schema (`p11.3.0`), non-empty `planId`/`generatedAt`, and ordering of baseline/evaluation/generated timestamps before computing anything [build-confidence-model.ts:buildConfidenceModel].
- A plan with zero objectives returns `buildEmptyModel` rather than throwing [build-confidence-model.ts:buildConfidenceModel], [build-confidence-model.ts:buildEmptyModel].
- `LearningEngine.run` throws `LearningEngineError` with a remediation hint when no strategic plan exists [confidence-learning-engine.ts:LearningEngine].
- Explain traversal is bounded by `EXPLAIN_DEFAULT_DEPTH = 5` and `EXPLAIN_MAX_DEPTH = 12` [evidence-chain-types.ts:EXPLAIN_DEFAULT_DEPTH], [evidence-chain-types.ts:EXPLAIN_MAX_DEPTH].
- `EXTRACTORS` must cover every `ArtifactType` except `learning_evidence_chain`; unknown types fall back to an empty link list and chains never link chains [forward-ref-extractors.ts:EXTRACTORS], [forward-ref-extractors.ts:extractForwardRefs].
- `extractForwardRefs` normalizes `sourceArtifactId`/`sourceArtifactType` to the caller's view of identity [forward-ref-extractors.ts:extractForwardRefs].
- The dashboard integrity score is a derived operational metric, never written back into governance state; it returns 0 deterministically when no explanations exist and is clamped to `[0, 100]` rounded to one decimal [dashboard-integrity-score.ts:computeDashboardIntegrityScore].
- Dashboard output is pure read-only aggregation over `OutcomeStore`, the explain assembler, and `LearningStore`; it mutates nothing [learning-dashboard.ts:buildDashboardReport].

## Side Effects
- Appends signals, profiles, and reports to `signals.jsonl`, `profiles.jsonl`, and `reports.jsonl` under the configured store directory, creating it if absent [learning-store.ts:LearningStore].
- Appends confidence models to `confidence-models.jsonl`, creating the store directory when missing [confidence-model-store.ts:ConfidenceModelStore].
- Appends evidence chains to `.alix/learning/evidence-chains.jsonl`; the default store directory is `join(process.cwd(), ".alix", "learning")` [evidence-chain-store.ts:EvidenceChainStore].
- `runLearningRefresh` reads `.alix/adaptation/outcomes`, `.alix/risk-scores`, and `.alix/governance-reviews` when it builds the default adapter registry [learning-refresh.ts:runLearningRefresh].
- `runLearningRefresh` writes to `LearningStore` at `<cwd>/.alix/learning` and logs append failures with `console.error` [learning-refresh.ts:runLearningRefresh].
- `buildDashboardReport` reads `<cwd>/.alix/adaptation/outcomes` and `<cwd>/.alix/learning`, and calls the explain assembler per recent proposal [learning-dashboard.ts:buildDashboardReport].
- `LearningEngine.run` reads the latest strategic plan, outcome records, baseline and current score snapshots, then persists one model via `ConfidenceModelStore.save` [confidence-learning-engine.ts:LearningEngine].
- Builder signal and profile IDs are derived from `Date.now()`; identical inputs at different instants yield different IDs [recommendation-calibration-builder.ts:RecommendationCalibrationBuilder], [risk-calibration-builder.ts:RiskCalibrationBuilder], [governance-calibration-builder.ts:GovernanceCalibrationBuilder], [routing-calibration-builder.ts:RoutingCalibrationBuilder].
- `extractForwardRefs` falls back to `new Date().toISOString()` for `recordedAt` when an artifact carries no timestamp [forward-ref-extractors.ts:extractForwardRefs].
