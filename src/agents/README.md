# Agents

## Overview

Owns the model-facing built-in tool contract, role/subagent dispatch, coordination objective review, and the fail-closed qualification surface for isolated worker execution. Main-agent behavior lives in [./agent/README.md](./agent/README.md); this directory owns the boundary that decides which exact names a turn may call, which tools a role may see, and whether a worker launch has enough trusted evidence to proceed.

## Invariants

- Only exact offered names execute. An executor id, legacy alias, or unoffered `alix_*` name is never accepted; `mcp__*` handles require a matching `mcp.` exec name `[tool-name-resolver.ts:resolveExecutableToolName]`.
- Every built-in has distinct callable and dispatch names, and the reverse map is derived from the forward map so the two cannot drift `[tool-manifest.ts:ALIX_EXECUTOR_TO_MODEL_FACING]`.
- Role policy is deny-by-default for unlisted tools; completion remains callable, and MCP tools are admitted only when the policy allows them `[tool-policy.ts:filterTools]`.
- Read-only roles get read tools with 5 iterations and 3 shell commands; write roles get read/write/MCP with 5 and 5; research roles get read/MCP with 5 and 3; the fallback is read-only with 3 and 2 `[tool-policy.ts:getToolPolicy]`.
- A delegated worker without `ownedPaths` fails non-retryably rather than receiving an unbounded write scope `[delegate-tool.ts:createDelegateHandler]`.
- `checkEssenceCompatibility` is advisory: it returns a 0–100 score and a `compatible` threshold verdict, never work assignment or execution `[essence-profile.ts:checkEssenceCompatibility]`.
- Objective review applies only to `success` results; a rejection becomes `partial` when paths were mutated and `failed` otherwise `[coordination-objective-review.ts:reviewCoordinationResult]`.
- A `satisfied: true` verdict with nonempty gaps is malformed and takes the single retry path; an invalid verdict after retry fails closed `[coordination-objective-review.ts:reviewCoordinationResult]`.
- Every mutated path must have a readable persisted artifact, or the review rejects; complete artifacts are never silently clipped `[coordination-objective-review.ts:reviewCoordinationResult]`.
- Review evidence is bounded by `REVIEW_BUDGET_CHARS` by dropping older outputs with an explicit omission marker, never by failing a worker for thorough evidence `[coordination-objective-review.ts:boundEvidence]`.
- `SubagentResult.status` is an ownership verdict: zero writes with owned paths fails, zero writes without owned paths succeeds, and a partial write set yields `partial` `[subagent-cli.ts:computeSubagentStatus]`.
- Write-mode iterations with missing owned paths expose only `WRITE_TOOLS` plus `alix_done` on the final iteration `[subagent-cli.ts:toolsForSubagentIteration]`.
- Path inference is conservative: patch-path inference applies only to `patch.apply`, and pathless search/replace requires write mode, exactly one owned path, and exactly two blocks `[subagent-cli.ts:shouldInferPatchPath]`, `[subagent-cli.ts:pathlessSearchReplaceParts]`.
- A retryable write failure does not become fatal; successful changed paths remain evidence even after a later failed retry `[subagent-cli.ts:recordWriteOutcome]`.
- Result events are bounded to 200 events and 64 KiB, with an explicit `subagent.events.truncated` marker when either bound drops data `[subagent-cli.ts:MAX_RESULT_EVENTS]`, `[subagent-cli.ts:MAX_RESULT_EVENT_CHARS]`, `[subagent-cli.ts:serializeResultEvents]`.
- Child lifecycle and usage appends are best-effort; the stdout result is authoritative `[subagent-cli.ts:SubagentCLI.main]` `[subagent-manager.ts:emitLifecycle]`.
- A structured child failure is written to stdout in JSON mode so the parent keeps `status`/`findings`/`error` instead of seeing a bare crash `[subagent-cli.ts:formatSubagentResult]`.
- The startup gate accepts FD 4 only and requires the exact `GE04_READY\n` frame `[worker-supervisor-startup-gate.ts:awaitSupervisorStartupRelease]`.
- The credential snapshot requires an integer fd ≥ 3, an object (not array), and string values only `[credential-fd-reader.ts:readWorkerCredentialSnapshot]`.
- Child provider routing requires zero fallbacks in the qualified route contract `[worker-child-route-preflight.ts:assertChildProviderRouteSupported]`.
- Credential grants require a concrete resolved model, a provider-shaped identifier, and a deduplicated provider set; planning reads no credential values `[credential-grant-planner.ts:planWorkerCredentialGrant]`.
- `bindWorkerGrant` and `assertWorkerGrantUse` reject route or identity expansion, so a grant authorizes exactly its bound model `[worker-grant-binding.ts:assertWorkerGrantUse]`.
- `SIMULATED` route claims require the exact run/worker/attempt, owner, and plan revision; claim replay is checked against model and route revision `[worker-grant-record-check.ts:assertClaimedWorkerRecord]`, `[worker-route-claim-simulation.ts:assertSyntheticClaimReplay]`.
- Route evidence is a SHA-256 candidate fingerprint over the authorized model, not a caller-supplied string `[worker-route-authority.ts:captureSyntheticRouteEvidence]`.
- `WorkerSupervisor` is contract-only: the only implementations here are qualification prototypes, and `unavailableWorkerSupervisor` denies every operation `[worker-supervisor.ts:unavailableWorkerSupervisor]`.
- The Linux supervisor rejects same-UID launches, requires positive kernel start-time evidence, and re-reads process identity before registration `[worker-supervisor-linux.ts:createLinuxWorkerSupervisor]`.
- A failed qualification with an unresolved child is quarantined and blocks replacement launch until termination is confirmed `[worker-supervisor-linux.ts:createLinuxWorkerSupervisor]`.
- The native backend requires a root supervisor and refuses `requireKernelContainment` with a security hold rather than falling back to uncontained launch `[worker-supervisor-native-backend.ts:createNativeLauncherQualificationBackend]`.
- The native launcher is pinned by inode and reached through `/proc/self/fd/4`, with `shell` disabled and `PATH=/usr/bin:/bin` `[worker-supervisor-native-backend.ts:createNativeLauncherQualificationBackend]`.
- Admission custody is Linux-only, absolute-path, owner-name bounded to 1–128 safe characters, and fails closed if the parent is group/world-writable `[worker-supervisor-admission-custody.ts:claimAdmissionCustody]`.
- Custody is sticky across crashes: there is no stale-owner takeover or automatic claim removal `[worker-supervisor-admission-custody.ts:claimAdmissionCustody]`.
- The recovery gate refuses all launches until both unresolved records and launch intents are empty, and rechecks durable state on each launch `[worker-supervisor-recovery-gate.ts:createRecoveryGatedWorkerSupervisor]`.
- The admission coordinator serializes only in-process operations; it explicitly does not establish cross-process exclusivity `[worker-supervisor-admission-coordinator.ts:createSerializedAdmissionCoordinator]`.
- Durable launch writes the intent before spawn and never erases it after an uncertain outcome; promotion requires a registration-id match `[worker-supervisor-durable-launch.ts:createDurableLaunchWorkerSupervisor]`, `[worker-supervisor-recovery-ledger.ts:WorkerSupervisorRecoveryLedger]`.
- Mission recovery observation is read-only and never eligible: PID absence, a matching procfs generation, or cgroup `populated=0` cannot prove descendant containment `[worker-supervisor-kernel-recovery-observer.ts:observeKernelRecovery]`, `[worker-supervisor-recovery-assessment.ts:assessRecoveryEvidence]`.
- The pinned recovery probe always returns `status: 'blocked'`, even when the cgroup inode is stable `[worker-supervisor-pinned-recovery-probe.ts:probePinnedRecovery]`.
- Stop/attach/resume requires two matching stopped observations with an unchanged start time and successful cgroup membership verification before resuming `[worker-supervisor-stop-attach.ts:stopAttachVerifyResume]`.
- The cgroup v2 adapter requires a canonical leaf under `/sys/fs/cgroup/`, root-owned directory components and control files, and confirms kernel-reported attachment `[worker-supervisor-cgroup-v2.ts:WorkerCgroupV2.open]`, `[worker-supervisor-cgroup-v2.ts:WorkerCgroupV2.attachStoppedChild]`.
- Containment discovery and observation always return `supportedForQualification: false` and `authorizedForWorkerLaunch: false`; read-only evidence never authorizes launch `[linux-containment-discovery.ts:discoverLinuxContainment]`, `[linux-containment-observer.ts:observeLinuxContainment]`.
- Runtime classification treats conflicting or absent markers as `unknown` and sets `eligibleForContainment: false` `[linux-container-runtime-evidence.ts:classifyLinuxRuntime]`.
- Broker authorization is HMAC-SHA256 over the claim with a key of at least 32 bytes, a 1–60 second TTL, and a single-use nonce `[worker-broker-authorization.ts:createIsolatedBrokerAuthorizer]`.
- Governed broker admission checks the peer policy, live claim match, authorization ticket, and replay-ledger consumption before admitting `[worker-broker-governed-admission.ts:createGovernedBrokerAdmission]`.
- A broker peer must present kernel Unix peer credentials, must not be the broker UID, and must appear in the allowed worker UID list `[worker-broker-ipc-boundary.ts:assertBrokerPeer]`.
- Replay nonces are exactly 48 lowercase hex characters, unexpired, and consumed with `INSERT OR IGNORE` so concurrent replays lose the race `[worker-broker-ipc-boundary.ts:BrokerReplayLedger.consumeAuthenticated]`.
- Broker transport requires an absolute socket path and an OS attestor; the socket is paused during attestation and destroyed on timeout, and `OK\n` is sent only after authorization `[worker-broker-transport.ts:createBrokerProbeServer]`.
- Process identity reads bracket `/proc/<pid>/status` with two stat reads and reject a UID transition, so a recycled PID is not accepted `[worker-broker-linux-process.ts:readLinuxProcessIdentity]`.
- Live peer bindings are frozen, reject duplicate PIDs, and re-read the process on resolve to recheck UID and start time `[worker-broker-live-peer-binding.ts:BrokerLivePeerBindings]`.
- A native probe requires distinct broker and allowed UIDs, an absolute executable and socket, a 1–30 second timeout, no shell or stdin, and bounded stdout/stderr `[worker-broker-supervised-probe.ts:runSupervisedNativeProbe]`.
- `admitNativeDiagnosticHandoff` always throws the diagnostic security hold; it never admits a native handoff `[worker-broker-native-admission-gate.ts:admitNativeDiagnosticHandoff]`.
- Native peer handoff parsing is strict: peer identity must match the Unix-credentials shape and the frame is bounded to 128 characters `[worker-broker-native-handoff.ts:parseNativePeerHandoff]`.
- The pinned native executable must be root-owned, opened with `O_NOFOLLOW`, and match the observed device/inode and realpath `[worker-broker-native-executable.ts:qualifyNativeProbeExecutable]`.
- `spawnPinnedNativeProbe` requires a trusted launcher and a qualified executable, pins the executable on FD 3, and disables the shell `[worker-broker-pinned-probe.ts:spawnPinnedNativeProbe]`.
- The peercred helper must be root-owned, non-symlinked, and opened through a pinned descriptor; `openPinnedPeercredHelper` returns that descriptor `[worker-broker-trusted-helper.ts:assertTrustedPeercredHelper]`, `[worker-broker-trusted-helper.ts:openPinnedPeercredHelper]`.
- Linux peer-credential attestation requires an absolute trusted helper path, uses `SO_PEERCRED`, and bounds the exchange to one second `[worker-broker-linux-peercred.ts:createLinuxPeerCredentialAttestor]`.
- The synthetic credential snapshot must exactly match the planned provider set and is test-only `[credential-grant-fixture.ts:projectSyntheticCredentialSnapshot]`.
- `projectWorkerConfigView` is test-only and requires a concrete model with unique providers; the first provider match supplies the view `[worker-config-view.ts:projectWorkerConfigView]`.
- `createSyntheticGrantAuthority` is explicitly not a production trust boundary `[worker-grant-authority.ts:createSyntheticGrantAuthority]`.
- The synthetic grant issuer advances attempts monotonically and consumes a grant once `[worker-grant-issuer.ts:createSyntheticGrantIssuer]`.
- The precredential route gate requires a running worker whose attempt, owner, and trusted snapshot match the claim `[worker-precredential-route-gate.ts:assertPrecredentialWorkerRouteClaim]`.

## Side Effects

- `SubagentManager.spawn` acquires ownership leases for write tasks with owned paths, renews them while running, and releases them before the spawn promise resolves `[subagent-manager.ts:acquireTaskOwnership]`, `[subagent-manager.ts:releaseTaskOwnership]`, `[subagent-manager.ts:spawn]`.
- A partial lease acquisition rolls back the leases it already acquired `[subagent-manager.ts:acquireTaskOwnership]`.
- `SubagentManager.spawn` writes the resolved credential snapshot to child FD 3 and, when a lifecycle observer exists, gates startup on FD 4 `[subagent-manager.ts:spawn]`.
- `SubagentManager.spawn` emits spawned, task-assigned, and ownership lifecycle events fire-and-forget `[subagent-manager.ts:spawn]`, `[subagent-manager.ts:emitLifecycle]`.
- `SubagentManager.shutdown` bumps the spawn epoch, kills running children, and clears the task map so late spawns cannot register `[subagent-manager.ts:shutdown]`.
- `SubagentManager.terminateProcessTree` signals the POSIX process group first, falls back to the child PID, and kills the child directly on Windows `[subagent-manager.ts:terminateProcessTree]`.
- `SubagentCLI.main` installs a parent-liveness watchdog that exits 1 when the parent stdin closes, except on a TTY `[subagent-cli.ts:installParentLivenessWatchdog]`.
- `SubagentCLI.main` reads the credential snapshot from FD 3 after the optional startup release and precredential gate `[subagent-cli.ts:SubagentCLI.main]`.
- A missing approval store fails closed and emits `subagent.approval_store_unavailable` `[subagent-cli.ts:SubagentCLI.main]`.
- MCP initialization failure is non-fatal: the child continues without MCP tools `[subagent-cli.ts:SubagentCLI.main]`.
- `WorkerSupervisorRecoveryLedger` opens a SQLite database with WAL and `synchronous=FULL`, and refuses an existing file that is not owned by the effective UID or is group/world-accessible `[worker-supervisor-recovery-ledger.ts:WorkerSupervisorRecoveryLedger]`.
- Recovery-ledger launch intents are written in a transaction before spawn and promoted atomically after qualification `[worker-supervisor-recovery-ledger.ts:beginLaunch]`, `[worker-supervisor-recovery-ledger.ts:promoteLaunch]`.
- `claimAdmissionCustody` creates the custody directory with mode `0o700`, writes `owner.json` with `0o600` and `fsync`, and deliberately leaves a partial claim in place `[worker-supervisor-admission-custody.ts:claimAdmissionCustody]`.
- `createLinuxWorkerSupervisor` terminates a failed qualification child and retains it in quarantine if termination fails `[worker-supervisor-linux.ts:createLinuxWorkerSupervisor]`.
- `createNativeLauncherQualificationBackend` spawns detached, closes the pinned launcher descriptor, and kills the process group on failed qualification `[worker-supervisor-native-backend.ts:createNativeLauncherQualificationBackend]`.
- `WorkerCgroupV2` writes `cgroup.procs` to attach and `cgroup.kill` to kill the tree `[worker-supervisor-cgroup-v2.ts:WorkerCgroupV2.attachStoppedChild]`, `[worker-supervisor-cgroup-v2.ts:WorkerCgroupV2.killTree]`.
- `stopAttachVerifyResume` attempts both cgroup kill and child termination on failure and leaves the durable intent unresolved if clean containment is unproven `[worker-supervisor-stop-attach.ts:stopAttachVerifyResume]`.
- `createBrokerProbeServer` listens on the supplied Unix socket path, destroys unauthorized or timed-out connections, and ends authorized ones with `OK\n` `[worker-broker-transport.ts:createBrokerProbeServer]`.
- `BrokerReplayLedger` creates a `broker_nonce` table in its SQLite database and inserts consumed nonces `[worker-broker-ipc-boundary.ts:BrokerReplayLedger]`.
- `createLinuxBrokerProcessRegistry` registers and revokes broker processes; registration is supervisor-only and resolves the live identity on demand `[worker-broker-linux-registration.ts:createLinuxBrokerProcessRegistry]`.
- `discoverLinuxContainment` and `observeLinuxContainment` perform read-only reads of `/proc` and `/sys` evidence and never write cgroupfs or signal a process `[linux-containment-discovery.ts:discoverLinuxContainment]`, `[linux-containment-observer.ts:observeLinuxContainment]`.
- `SubagentCLI.main` appends lifecycle and `model.usage` events on a best-effort basis `[subagent-cli.ts:SubagentCLI.main]`.
