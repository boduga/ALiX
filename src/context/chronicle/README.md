# Chronicle Store

## Overview
Structured case memory for SignalFrame outcomes. Each entry records the observed problem, diagnosis, prescribed action, actual outcome, lesson, and supporting references, with a compact index for retrieval.

## Interface
- `ChronicleEntry` and `ChronicleOutcome` describe the full case record and its outcome vocabulary [chronicle-store.ts:ChronicleEntry]
- `ChronicleStore.append(entry)` generates identity and timestamp, writes the full entry, and updates the index [chronicle-store.ts:ChronicleStore.append]
- `ChronicleStore.get(entryId)` retrieves a full entry or `undefined` [chronicle-store.ts:ChronicleStore.get]
- `ChronicleStore.search(query)` filters by domain, polarity, outcome, and signal code [chronicle-store.ts:ChronicleStore.search]

## Invariants
- `entryId` and `createdAt` are generated by the store and cannot be supplied by callers [chronicle-store.ts:append]
- The index retains only summary fields, while signal-code filtering happens after loading the full entry [chronicle-store.ts:search]
- Search filters combine with AND semantics and missing or malformed entries are skipped rather than causing failure [chronicle-store.ts:search]
- A missing or unparseable index loads as an empty array [chronicle-store.ts:loadIndex]

## Side Effects
- Append creates `.alix/chronicle` and `.alix/chronicle/entries` and writes `<entryId>.json` plus `index.json` [chronicle-store.ts:append]
- Search and get read the chronicle directory from the supplied root; no other stores are modified [chronicle-store.ts:search]
